Quick start

Ask the server owner for the service base URL and your shared secret. Send a JSON request to POST /route with Authorization: Bearer YOUR_SHARED_SECRET. This example uses coordinates and needs no configured labels:

curl -X POST "https://routes.example.com/route" \
  -H "Authorization: Bearer YOUR_SHARED_SECRET" \
  -H "Content-Type: application/json" \
  --data '{"from":{"coordinates":{"latitude":29.7604,"longitude":-95.3698}},"to":{"coordinates":{"latitude":29.7499,"longitude":-95.3584}}}'

These examples are illustrative. Substitute your service URL, secret, and locations. In Windows Command Prompt, use a JSON file and --data-binary @request.json instead of shell-specific quoting.

Locations

For easier Postman testing, import the distributed NoPartRoutes.postman_collection.json. In the collection's Variables tab, set baseUrl (without a trailing slash), sharedSecret, fromType, fromValue, toType, and toValue. Types are label, address, pluscode, or coordinates; coordinate values use latitude,longitude. Send the Route — build JSON from fields request. It builds and escapes JSON automatically and supplies Bearer authorization. The Google key stays on the server.

from and to each contain exactly one of these forms. You may mix forms in the same request.

{"label": "home"}
{"address": "100 Example Street, Example City"}
{"pluscode": "849VCWC8+R9"}
{"coordinates": {"latitude": 29.7604, "longitude": -95.3698}}

Plus codes identify locations without street addresses. Use a full code such as 849VCWC8+R9, or a compound code with locality such as CWC8+R9 Mountain View, CA, USA. A shortened code without locality is ambiguous. Send the literal + in JSON and INI files; the server URL-encodes it for Google. Google validates and resolves the code through Geocoding.

Labels are defined by the owner in locations.ini. Label comparison ignores case and surrounding whitespace. An unknown label is an error, never an address fallback. Public discovery does not list real locations; authenticated clients can use GET /locations.

List saved locations

Send GET /locations with the same Authorization: Bearer YOUR_SHARED_SECRET as route requests. It returns loaded labels and user-configured values without calling Google or consuming daily call limits:

{
  "locations": {
    "home": {"address": "100 Example Street, Example City"},
    "meeting": {"pluscode": "849VCWC8+R9"},
    "work": {"coordinates": {"latitude": 29.7604, "longitude": -95.3698}}
  }
}

Labels are returned in normalized lowercase form. An empty configuration returns {"locations":{}}. Save locations.ini to add, change, or remove labels without restarting. The next route or locations request after a 0.5-second settling interval uses the latest valid file. Invalid or unreadable edits keep the previous valid labels and log a warning in logs/application.log. Each route uses one complete snapshot. An empty valid file removes all labels. Newly added addresses and plus codes resolve when first used. All valid shared secrets can read these values. Responses omit credentials, notes, and Google cache data and use Cache-Control: no-store. The Postman collection includes a Locations request.

Addresses must be nonempty. Coordinates must be finite numbers: latitude from −90 to 90 and longitude from −180 to 180. Extra fields, duplicate JSON fields, and conflicting forms are rejected. Request bodies are limited to 16 KiB and require Content-Length; chunked uploads are unsupported.

{
  "from": {"label": "home"},
  "to": {"coordinates": {"latitude": 29.7604, "longitude": -95.3698}}
}

Response and traffic

{
  "driveMinutes": 18.4,
  "distanceMiles": 7.26,
  "summary": "Example route description",
  "usesTolls": true,
  "avoidTolls": {
    "driveMinutes": 24.2,
    "distanceMiles": 9.15,
    "summary": "Example route avoiding tolls",
    "usesTolls": false
  },
  "avoidTollsError": null
}

driveMinutes is numeric minutes rounded to one decimal. distanceMiles is numeric miles rounded to two decimals. summary is Google's route description or null when unavailable. Numbers may serialize without trailing zeroes. The body always has exactly six top-level fields. The example is illustrative.

Every request first calculates a Google-recommended driving route with tolls allowed and TRAFFIC_AWARE. The server omits the upstream departure timestamp so Google uses the time of the request as departure now. This avoids rejected past timestamps caused by network latency or clock differences. These are estimates for leaving now, not guarantees. There are no caller-selectable departure times or travel modes, and failed calls never return an old traffic estimate.

usesTolls reports Google's toll detection, including tolls with unknown prices. If true, the server makes one additional request asking Google to avoid tolls and puts its estimate in avoidTolls. Both calculations use the same resolved locations and current traffic. If the primary route has no tolls, avoidTolls and avoidTollsError are null and only one Routes call is needed. Toll prices are not returned.

Google's avoid-tolls setting is a preference: the alternative may still have usesTolls: true. The server never makes a third request. If the second calculation fails or is blocked by a daily limit, HTTP 200 preserves the primary result, avoidTolls is null, and avoidTollsError contains its safe code and message. Otherwise avoidTollsError is null. Each outbound Routes attempt consumes the daily cap separately. No additional Postman fields are needed; reimport the collection for updated response checks.

Location caching

Named and direct addresses and plus codes share a CSV-backed resolution cache. Google place IDs are reused; each route still requires a fresh Routes call. User-supplied coordinates bypass geocoding. Saved uncached addresses and plus codes are warmed at startup, and new locations are resolved on first use.

The service stores place IDs, not Google-returned coordinates or formatted addresses. Any legacy Google coordinates present in the cache are cleared on expiry within their 30-day retention limit. Reading an entry never renews its expiry. A retained place ID can remain usable after coordinate expiry.

A separate Geocoding API lookup costs an additional call on a cache miss. Caching avoids repeat explicit geocoding; it does not promise lower overall charges than passing addresses directly to Routes.

Authentication

All configured shared secrets grant the same access. Names such as Muse or Grok and their notes are reminders for the owner only. Secrets are case-sensitive and manually managed; there is no account system or automatic exchange. Never put a secret into a URL. Shared-secret and server-setting changes require restarting the service. Location-file edits reload automatically.

/route and /locations require a valid shared secret. /version, /docs, /openapi.json, and /health are public. Health reports liveness and does not check Google credentials or quota.

Detect changes and refresh instructions

{
  "apiVersion": "{{API_VERSION}}",
  "docsVersion": {{DOCS_VERSION}},
  "docsUrl": "docs",
  "openapiUrl": "openapi.json"
}
  1. Read /version on first connection and at the start of each session.
  2. If either version differs from your remembered version, or you have no saved instructions, read /docs and /openapi.json before calling routes.
  3. Remember the versions of the instructions you read. Watch X-No-Part-Routes-API-Version and X-No-Part-Routes-Docs-Version on all responses. Refresh instructions before the next route call when either changes.
  4. Stop calls if the refreshed contract is incompatible with your integration, until the integration is updated.

Release versions use the date-based YY.MM.DD format. The version number does not encode compatibility: refresh the contract when it changes and check that your integration supports it. Documentation revision increases for any published instructions or contract change, including documentation-only edits. Clients must implement the refresh behavior themselves.

Resolve returned documentation links relative to the service base URL with a trailing slash, including any reverse-proxy prefix. If your base is https://example.com/routes/, the docs URL is https://example.com/routes/docs. All responses use Cache-Control: no-store.

Errors

The owner can set daily Google-call limits. When a local limit is exhausted, a blocked primary route returns 429 DAILY_USAGE_LIMIT without making the blocked Google call. If the optional avoid-tolls request is blocked, the primary route returns HTTP 200 with that code in avoidTollsError. Limits count attempted Routes and Geocoding calls separately, including failures and startup warming, and reset at midnight UTC. Counts survive server restarts. They are local guards, not Google's billing totals. If usage counters cannot be saved, Google calls are blocked with 503 USAGE_STORAGE_UNAVAILABLE.

Each response includes X-No-Part-Routes-Request-ID. Give that ID to the server owner to find related request, cache, and Google-call records in the private rotating application log. Logs do not contain secrets, addresses, plus codes, coordinates, route descriptions, or request bodies.

Displaying Google results

Interfaces displaying these results must follow Google's attribution and policy requirements, including Google Maps branding when results are displayed without a map, and use of a Google Map when displaying results on a map. Integration owners must provide the required Terms of Use and Privacy Policy. This API's response does not satisfy those display obligations on its own.

Prefer the official Google Maps logo. If space prevents its use, display Google Maps text with Google's required styling near the results. Attribution must be visible even when summary is null; text buried in JSON alone does not satisfy display requirements.
